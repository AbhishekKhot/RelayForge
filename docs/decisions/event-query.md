# C2 event query and delivery summary

`GET /v1/events/{event_id}` uses the authenticated organization's `events:read` scope. The control-plane check accepts only `events:read` or its existing default `events:write`; fresh provisioned keys include both. The ingestion query decodes the versioned locator to select the local logical shard and acceptance day, then queries `events` by organization, day, and event UUID. Malformed locators, wrong shards, missing rows, and other organizations return the same `404`. The locator supplies a route, never authorization.

The response includes event acceptance fields and a payload bounded to 512 KiB after PostgreSQL JSON rendering. It omits registry, outbox, ciphertext, and internal diagnostics. Delivery progress comes only from a credential-protected delivery API read of its own database. Before `routing_progress` exists, the summary is `PENDING` with zero observed counts. Once routing creates progress and deliveries, the same internal read reports current status and counts. An unavailable, malformed, or oversized delivery response makes the public read return `503` rather than fabricating progress.

The internal client disables redirects, uses 2-second connection and 3-second request timeouts, caps the response at 4 KiB, and closes the response stream. Both the delivery URL and a generated internal credential come from ignored `.env`; the delivery API rejects missing or incorrect credentials before querying. The delivery SQL predicates on organization, event UUID, and acceptance day and uses indexed event access. This follows the [LLD locator and read contract](../../RelayForge_Low_Level_Design.md), [RFC 9110's 404 concealment semantics](https://www.rfc-editor.org/rfc/rfc9110.html), [Java 21 HTTP response handling](https://docs.oracle.com/en/java/javase/21/docs/api/java.net.http/java/net/http/HttpResponse.BodyHandlers.html), and [PostgreSQL SELECT semantics](https://www.postgresql.org/docs/17/sql-select.html).
